## 二、问题清单（按「只在 GitHub 维护」这个新前提排序）

### P0 — 挡在门口的

**① 别人打开仓库首页，看到的是一份过期的薄 README**
`README.md` 只有 37 行，且**语义已过期**：写着「`Web-version/` 网页派生站点，**待建**」，
而实际 19/19 已全部建成上线。开篇还劝人「GitHub 不渲染 HTML，请 clone 到本地看」——
这在「GitHub 是唯一维护面」的新前提下正好说反了：**首页应该是最好的入口，不是劝退页**。

**② 网页版在线不可读**
19 册网页版是这个库最好的一面，现在只有 clone 下来才能看。而它离在线可读只差两步：
- **`.nojekyll` 缺失（致命）**：GitHub Pages 默认走 Jekyll，Jekyll **会跳过所有下划线开头的目录**
  ——本库的 `_assets/`（全站 CSS）、`_prep/`（实战包/学习路径/一页纸）正好全中。
  不加这个文件，页面上线即掉样式、取用页全 404。
- **根目录没有 `index.html`**：Pages 首页只认 `index.html`，本库门户叫 `README.html`。

好消息：全站链接**已经全是相对路径**（实测根 README.html、Web-version/index.html、
模块页三层都是 `./` `../` 开头），Pages 与 file:// 双击两种打开方式可以同时成立，
Portable 铁律不用破。

**③ 公开仓库没有 LICENSE**
没有许可证 = 默认「保留所有权利」，法律上**别人不能合法使用你的技能**。
而「让别人下载技能去用」正是这次改造的目标之一。这是必须补的一块。

### P1 — 拿掉之后维护会明显变轻的

**④ 门禁只跑在你这台机器上**
库里最值钱的资产之一是那十道门禁 + 一堆血泪教训（画布错配、XML 非良构、语义过期……）。
但它们全靠「记得手动跑」。GitHub 化之后，这些应该由 CI 在每次 push 时无条件执行——
**这是本次改造收益最大的一项**。

**⑤ 「只下载技能」这条路没有正经出口**
现在只能靠 raw URL 拖一个 232 K 的 zip：没有版本号、没有发布说明、没法知道自己拿的是哪一版、
更新了也不会有人知道。GitHub 原生的答案是 **Release + 资产**。

**⑥ 用 42 个 zip 副本在扮演 git 的角色**
`_skill-source/history/` 42 个 .skill（6.4 M）、`_maintenance/history/` 21 个文件，
做的事情正是 git 本身该做的事。技能每升一版就多一个不可 diff 的二进制副本。
GitHub 化之后正确做法是 **tag + Release**。

**⑦ 「所有版本都在 GitHub」与 `raw-data/history/` 直接冲突**
49 MB、约 170 份历史 pptx 被 `.gitignore` 挡在库外，**只存在于你这一台机器上**。
现有 README 的理由是对的（pptx 二进制不可 diff，版本历史交给 git 承担）——
既然如此，这个目录在新前提下已经**完全冗余**，缺的只是一份「怎么从 git 里取回某天的讲义」的操作说明。

### P2 — 该有但不急的

**⑧ 没有 `.gitattributes`**：pptx / .skill 未标 binary；跨平台换行未定；
中文文件名在 git 输出里被转义成 `\344\277\256...`（`core.quotepath`）。

**⑨ 保鲜巡检还是本地定时任务**：库里已有「建议复查日」这套机制（MANIFEST 时效性事实 →
`fresh.html` 保鲜看板），但到期提醒靠本机 scheduled task。GitHub 有更合适的载体：
定时 workflow + 自动开 Issue。

**⑩ 网页版里指向 `.md` 的链接在 Pages 上是裸文本**
模块页链到 `../../PPT-version/MCP/电子书书单.md`、`MANIFEST.md`，file:// 下是纯文本（可接受），
Pages 上同样是纯文本（GitHub 上本来能渲染得很好看）。

## 三、改造设计

### 阶段一 · 门面与在线可读（P0）

**1. `.nojekyll`（库根，空文件）**
一行字的改动，但它是 Pages 能不能用的开关。附一句注释说明为什么（`_` 开头目录会被 Jekyll 吞掉）。

**2. 库根新增 `index.html`**
极简重定向页（`<meta http-equiv="refresh">` + 一个显式 `<a href="./README.html">` 兜底链接），
不引 `kb.css`——避免踩 `check_css_classes` 的版本戳对账。
`README.html` 作为门户的地位、以及全库所有「双击 README.html」的表述**一律不动**（外科手术式改动）。

**3. 开启 GitHub Pages**：source = `main` 分支 / 根目录。
站点地址 `https://jasonlijiaxiang.github.io/myailearning-claudecode/`。

**4. 重写 `README.md` 为真正的门面**，含：
   - 一句话定位 + 在线阅读入口（Pages 链接置顶）
   - 19 模块 / 七层书架总览表（从 MANIFEST 事实来，不手写第二份）
   - **两条下载路径**（本次改造的核心诉求）：整库怎么拿、只要技能怎么拿
   - 目录约定（修正「Web-version 待建」这处语义过期）
   - 门禁与 CI 徽章、许可说明
   - 保留现有「书单只列链接不存文件」的声明

**5. 仓库元数据**：description、homepage（指向 Pages）、topics
（`knowledge-base` / `claude-code` / `claude-skill` / `ai` / `chinese`）。

**6. `LICENSE` + `README` 许可段**——**待拍板，见第四节**。

### 阶段二 · 把纪律搬上 CI（P1 ④）

**7. `.github/workflows/gates.yml`**——push 到 main 与所有 PR 触发：
```
ubuntu-latest + python 3.11（不装任何依赖）
├─ 八道门禁逐个跑，各自独立报状态（哪道红一眼可见）
├─ python3 Web-version/build.py --check     # 网页产物与 MANIFEST 无漂移
├─ python3 _maintenance/audit_pptx.py       # 19 册讲义契约全检
├─ python3 _maintenance/check_skill_package.py _skill-source/knowledge-base-builder.skill
└─ 本机绝对路径扫描（portable 铁律，make_share 里那条正则提出来复用）
```

**8. `.gitattributes`**：`* text=auto eol=lf`、`*.pptx binary`、`*.skill binary`、
`*.pptx -diff`，以及 linguist 标注（让语言条别把 `_skill-source` 的 md 算成主体）。

**9. `.gitignore` 补**：`__pycache__/`、`*.pyc`、`/dist/`（分享包输出目录）。

### 阶段三 · 版本与分发（P1 ⑤⑥⑦）—— 用户诉求的正题

**10. `.github/workflows/release-skill.yml`**——推 tag `skill-v*`（如 `skill-v7.6`）触发：
```
从 _skill-source/knowledge-base-builder/ 现场打包
  → 跑 check_skill_package.py（结构自检，2026-07-20「这个包用不了」那次的教训）
  → 校验 tag 版本号 == SKILL.md frontmatter 的 version（对不上直接失败）
  → 建 Release，资产 = knowledge-base-builder-v7.6.skill
  → 发布说明从 references/CHANGELOG.md 抽当版那一段
```
于是「只下载技能」变成一句话：**去 Releases 下那个 `.skill`**。永久链接
`.../releases/latest/download/knowledge-base-builder.skill` 也一并提供（永远指向最新版）。

**11. `.github/workflows/release-kb.yml`**——推 tag `kb-v*`（如 `kb-v2026.07.29`）触发：
跑 `make_share.py`（它自带解压自检：解出来在里面把门禁全跑一遍 + 查死路径），
把产出的整库 zip 作为 Release 资产。于是「整体下载」有了不需要 git 的入口。

**12. 新增门禁 `_maintenance/check_skill_sync.py`**
校验受版本控制的 `.skill` 与 `_skill-source/knowledge-base-builder/` 源目录**逐文件内容一致**。
理由：库里保留一个可直接 raw 下载的 `.skill` 很有用，但一个不会被检查的二进制副本迟早会悄悄过期
——这正是本库反复吃过的亏（「搬运没错 ≠ 产物能用」）。挂进 CI。

**13. 冻结两个 history 目录**：`_skill-source/history/`、`_maintenance/history/` 现有内容**保留不动**
（不改写 git 历史），但从此**不再新增**——技能升版改走 tag + Release。
`.gitignore` 加规则挡住新文件，README 里写明「历史版本去 Releases / git tag 找」。

**14. `docs/从-git-取回历史讲义.md`**（或并入 README）：三行命令的操作说明——
`git log -- <路径>` → `git show <commit>:<路径> > 旧版.pptx`。
有了它，`raw-data/history/` 那 49 MB 就可以放心处置（**处置方式待拍板**）。

### 阶段四 · GitHub 原生的保鲜（P2 ⑨⑩，可选）

**15. `.github/workflows/patrol.yml`**：每月 1 号定时跑，从各模块 MANIFEST 抽出
「建议复查日」已过期的时效性事实，**自动开一个 Issue** 列清单（已有同名 Issue 则更新）。
把本机 scheduled task 换成仓库自己的记忆。需要新写一个小脚本 `check_freshness_due.py`。

**16. Issue 模板两个**：「内容过期报告」（读者发现数字过期）、「模块建议」。

**17. 网页版 `.md` 链接的 Pages 适配**：`site.js` 里加十几行——当页面跑在 `*.github.io` 上时，
把指向 `.md` 的相对链接改写成 GitHub blob URL（渲染版）；file:// 下行为完全不变。
这条要动 skill 的 web 面规则，**优先级最低，可以单独一批做**。

### 阶段五 · 文档与纪律回刷

**18. `CLAUDE.md` 增「四、GitHub 维护面」一节**：分支与提交口径、CI 绿了才算完

**19. `开始使用.html` 的「换一台机器」「整库怎么分享」两节改为 GitHub 优先**：
第一条路变成 `git clone`，压缩包降为备选；「装技能」一步改为从 Releases 取。

**20. 技能本体（`_skill-source/knowledge-base-builder/`）本次**：只在 `library-rules.md` 加一小节

### 两个只有接上 CI 才暴露出来的缺陷

**① `make_share.py` 自吞死循环（真缺陷，已修，技能升 v7.8）**
输出目录若在库内（`make_share.py dist`），走查会碰到**正在写的那个 zip 自己**——
读一段就压进去、文件随之变长，**永远读不到 EOF**：不是慢，是死循环 + 撑爆磁盘。
本机一直往库外或库根写，从没触发过；接上 CI 首跑即挂（跑到 5 分钟被手动取消）。
修法是跳过输出文件自身，两份副本同步修。
**教训**：同一个脚本换一种调用姿势就是**一条没验过的路径**，「本机跑通」证不到它。

**② Release 资产名被压成 `AI.-2026-07-29.zip`**
