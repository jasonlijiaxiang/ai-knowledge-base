# 全库内容打磨 · 技能自省（2026-07-23 起，07-29 收尾）

> 这一轮把 19 册网页版按「客户交锋」判据过了一遍。本文件记**该往
> `knowledge-base-builder` 里补什么规则**——不是记这轮干了什么（那在执行口径里）。
> 判据：一条经验只有在**下次会再犯**时才值得进技能。

## 一、最该进技能的一条：立题判据缺一把「覆盖尺子」

**现状**：技能的立题判据（有源 / 会改变一个决定 / 15–30 秒答得完 / 不同句）
全部是**单题质量**的尺子——它能判断一道题好不好，**判断不了少了什么题**。

**证据**：19 册的「现场高频追问」道道都过得了现有判据，但整整一轮打磨补出
50+ 道空白题，且空白高度集中在同几类客户异议上。首册实测 11 题里 6 题
是**技术选型题**（我们内部怎么做）而非**交锋题**（客户会把我问倒）——
这个分辨是全库通病，现有判据一个字都没提。

**建议补的规则**：把八个交锋战场作为**覆盖清单**写进 prep-rules 或 web-rules——
①效果给个数 ②周期/报价/人力 ③已经有 X 了 ④安全合规 ⑤换模型换厂商
⑥POC 怎么算成功 ⑦出问题谁负责 ⑧和别家不一样。
配一句纪律：**逐册画覆盖表，只补真空白；已覆盖的如实报「不补」——
重复的题比缺题更难清理。**

这一轮的实测支持它是好尺子：五批 19 册里，各册如实拒绝的战场累计 30+ 个，
LLM 一册拒了 5 个、Model-Landscape 拒了 5 个，没有出现「为凑满八项而硬写」。

## 二、三个自建脚本该入册

都是被这轮的真事故逼出来的，且**八道现有门禁一道都查不出**它们查的东西：

| 脚本 | 它查什么 | 为什么必须有 |
| --- | --- | --- |
| `check_new_numbers.py` | 扫 diff 新增行的数字，标注库内有无出处 | 我自己凭空写过「30–50 个真实问题」（库内既有口径是 20~50 题），通读没看出来，靠机器扫才抓到。**内容轮次里人一定会手滑造数字** |
| `check_html_wellformed.py` | 用真 XML 解析器过每页 `<article>` | 抓出 RAG 页一处**早就存在**的多余 `</div>`，八道门禁全放行。库内已有先例：07-17 讲义 1105 处非良构 XML，纯正则 audit 照样 PASS，只有渲染目检抓住——网页面有同一个盲区 |
| `check_count_claims.py` | 「三大偏差」下面却列了四条这类数目脱节 | 一天之内撞见三次（MCP 算术、MM 五层、Eval 三大）。客户会当场跟着数，数不上就显得材料不严谨。**报告型不是门禁**——脚本不懂语义，只摆候选 |

## 三、打磨轮次的两条纪律（现有规则没覆盖到的形态）

1. **零新增事实**：内容打磨轮次**一个新数字、新版本、新比例都不许加**；
   需要别册的数字一律**深链，不复制**。这是引用映射纪律在「打磨」这个动作上的
   具体形态，值得单列——因为打磨时人最容易觉得「补一句更完整」而顺手写个数。
   本轮实测有效：Model-Landscape 册执行者自己删掉了初稿里的「两周」，
   把「按周重跑」改成「定期」+ 深链，理由是那是 AI-Ops 的口径、复制即双源漂移。

2. **单面能不能改，取决于这处是不是两面同源**：本轮有多处该改不能改——
   AI-Infra-Compute「三个数量级」在讲义四页都这么写，改网页单面就是制造漂移；
   反过来，AI-Infra-Platform 那张图的「越往下越省心」是**网页面独有**且与
   讲义三页反向，就该当场改。**判据：先查真源有没有这句话，再决定动不动手。**

## 四、这轮暴露的、技能没错但值得写进巡检的

- **语义过期只能靠复查日 + 人**。收尾时发现 MCP / AI-Gateway / Agent 三册
  合计 11 处**前瞻承诺句**（「2026-07-28 发布 · 届时复核」）+ MCP 册 3 处
  **版本现状句**（「当前稳定规范 2025-11-25」）已经或即将不成立，讲义侧另有 16 页——
  八道门禁全绿，一道都查不出。
  巡检项建议加一条：**扫全库「届时/待复查/即将」类承诺句与「当前稳定/最新版」类
  现状句，逐条对今天的日期**。
  **写这条扫描规则时注意**：我第一版正则把「核实日 2026-07-07」和当作版本号用的
  「2025-11-25」也算成了到期承诺，虚报了一倍。**日期在这个库里有三种角色——
  承诺日、核实日、版本号——扫描必须靠上下文词区分，不能只匹配日期。**
- **建议复查日本身会过期而无人管**：AI-Gateway 的复查日 2026-07-23 已过期 6 天，
  没有任何机制提醒。巡检应把「复查日已过的册」列成第一项。
