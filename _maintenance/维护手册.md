# 维护手册

这个库**只在 GitHub 上维护**（2026-07-29 起）。本文是给维护者看的操作面：本地怎么验、
怎么提交、怎么发版、怎么换一台机器接手。内容规范与工作流不在这里，在技能
`knowledge-base-builder` 里。

## 需要什么

**Python 3.7+，系统自带的就行。** 门禁、网页生成器、打包工具**全部只用标准库**——不联网、不装包。
唯一的例外是改讲义 PPTX 的那批工具（配图、插页、缩放）需要 `python-pptx`；只读、只看网页、
只跑门禁都用不上它。

## 本地跑一遍门禁

改完东西、提交之前，在库根跑：

```bash
for g in check_kb_layout check_html_links check_page_ledger check_ebook_ledger \
         check_css_classes check_prep_coverage check_html_wellformed; do
  python3 _maintenance/$g.py >/dev/null 2>&1 && echo "OK   $g" || echo "FAIL $g"
done
python3 _maintenance/audit_pptx.py PPT-version/*/*-讲义.pptx | grep -c PASS
python3 Web-version/build.py --check
python3 _maintenance/check_skill_package.py _skill-source/knowledge-base-builder.skill
python3 _maintenance/check_skill_sync.py
```

哪道红了就单独跑那一道看详情（脚本都会打出具体是哪个模块、哪一行对不上）。

**门禁全绿 ≠ 内容对。** 语义过期（表述停在旧阶段、数字停在旧值）门禁查不出——
这库为此吃过好几次亏。收尾按 web-rules §九·五第 8 步核对门户三处表述。

## 提交与推送

单人库，**main 直提**，不走 PR。提交推上去之后 GitHub Actions 会把上面那套门禁
再无条件跑一遍（[gates.yml](../.github/workflows/gates.yml)）——本地忘了跑，CI 会拦。

**CI 红了不要往上叠提交**，先修红的那一道。仓库首页的门禁徽章反映的是 main 的当前状态，
它红着就等于对外说"这份库现在是坏的"。

## 发版：两条线

版本都在 GitHub 上，靠**标签**区分，不再往库里堆 zip 副本。

**① 技能发版**——改完技能源目录 `_skill-source/knowledge-base-builder/` 之后：

```bash
# 1. 重打库内那份分发包（check_skill_sync 会盯着它与源一致）
cd _skill-source/knowledge-base-builder && zip -rXq ../knowledge-base-builder.skill . -x '*.DS_Store' && cd ../..
python3 _maintenance/check_skill_sync.py
# 2. 提交，然后打标签（版本号必须与 SKILL.md 的 metadata.version 一致，对不上 CI 直接失败）
git tag skill-v7.6 && git push origin skill-v7.6
```

推上去之后 [release-skill.yml](../.github/workflows/release-skill.yml) 会从**源目录现场**
重打一份、过两道自检、建 Release 并把 `.skill` 挂上去。发布说明从技能内
`references/CHANGELOG.md` 的速查表取当版那一行——**发版前先把那一行补上**，
否则发布说明只有一句"没有本版条目"。

**② 整库发版**——想给不用 git 的人一个开箱即用的包：

```bash
git tag kb-v2026.07.29 && git push origin kb-v2026.07.29
```

[release-kb.yml](../.github/workflows/release-kb.yml) 会跑 `make_share.py`（自带解压自检：
把包解开、**在解出来的那份里**把门禁全跑一遍）再建 Release。

## 网页版怎么上线

GitHub Pages 从 **main 分支根目录**发布，没有构建步骤、没有 gh-pages 分支——
库里是什么样，站点就是什么样。改完内容 push 上去，一两分钟后线上就变了。

两个文件撑着这件事，**别删**：

- **`.nojekyll`**（空文件）：Pages 默认走 Jekyll，而 Jekyll **会跳过所有下划线开头的目录**
  ——本库的 `_assets/`（全站 CSS）、`_prep/`（三份取用页）正好全中。删了它，
  线上立刻掉样式、取用页全 404。
- **`index.html`**（跳转页）：Pages 首页只认 `index.html`，本库门户叫 `README.html`。

`robots.txt` 禁止搜索引擎收录（用户 2026-07-29 定）。它只管 Pages 站点；
github.com 上的仓库页本身是公开可搜的，那不归它管。

## 换一台机器接手

```bash
git clone https://github.com/jasonlijiaxiang/ai-knowledge-base.git
cd ai-knowledge-base
# 跑一遍上面那套门禁，全绿说明这份拷贝是完整的
```

然后按库根 [CLAUDE.md](../CLAUDE.md) 第零节补三样东西：技能
`knowledge-base-builder`（库内 `_skill-source/knowledge-base-builder.skill`）、
插件 `superpowers`、插件 `andrej-karpathy-skills`。**缺了不会报错，只会静悄悄地少一层保障。**

库里不存任何本机绝对路径（CI 有一道专门的扫描盯着），clone 到哪个目录都能跑。

## 目录里那些下划线开头的

`_prep/` `_maintenance/` `_reference/` `_skill-source/` —— 下划线开头 = 非知识模块，
不进模块列表。这是库的约定，不是 Python 私有约定。
