## 一、判据（一句话）

> **一处内容值不值得打磨，看它对应哪个客户会问的场合；说不出场合的，就不补。**

不是「机制讲没讲透」——那是学院派尺子，本库画像明写「重底层概念与取舍，**不啃重理论**」。
机制是**应对现场追问的弹药**，不是目的。首册第一版就是栽在这里（记在 RAG 设计文档文末）。

## 二、八个通用交锋战场（逐册比对，只补真缺的）

| # | 客户会问的那句话 | 本质 |
| --- | --- | --- |
| 1 | 效果能做到多少？给个数 | 承诺与验收——**最危险**，一个数字承诺出去后面全是坑 |
| 2 | 多久能上线？多少钱？ | 报价、周期、**人力账**（最常漏） |
| 3 | 我们已经有 X 了，凭什么再上一套 | 增量价值（且不能贬低对方已有投资） |
| 4 | 会不会泄露 / 能不能过审 | 安全、权限、合规 |
| 5 | 以后换模型 / 换厂商是不是全部重做 | 锁定与演进 |
| 6 | 先做个 POC——怎么算成功 | 验收标准，事前签不事后争 |
| 7 | 出了问题怎么查、谁负责 | 运维责任与排障 |
| 8 | 你们和某某家有什么不一样 | 竞争与差异化 |

**不是每册都要八个**。逐册看现有「现场高频追问」覆盖了哪些，只补真空白；
已覆盖的如实报「已覆盖，不动」——**重复的题比缺题更难清理**。

## 三、一册的动作

1. **诊断**：列现有追问 → 对八战场画覆盖表 → 判定缺口（通常 2–4 个）。
   注意分辨：**技术选型题**（我们内部怎么做）≠ **交锋题**（客户会把我问倒）。
   首册实测 11 题里 6 题是选型题，真战场反而空——这是全库通病，重点查。
2. **补题**：每题过实战包立题判据——有源 / 会改变一个决定 / 15–30 秒答得完且有可复述判据 /
   不与已有题同句。格式沿用该页既有 `<details>` 结构（summary + a + qa-why + qa-next + qa-src）。
3. **补机制**：只补**支撑新题**的那一点，写在正文对应章。补不出「服务哪个战场」的，不补。
4. **顺手纠错**：读到明确错误或误导性类比就改（首册即抓到 HNSW 被写成 IVF 语义）。

## 四、铁律：零新增事实

**一个新数字、新版本、新比例都不许加。** 所有数字必须是该册页面或其 MANIFEST 里**已有的**；
需要别册的数字就**深链过去**，不要复制（防双源漂移）。

**收尾必做的数字自查**（首册教训——通读会漏，必须机器扫）：

```
python3 _maintenance/check_new_numbers.py        # 扫 diff 新增行的数字并标注库内有无出处
```

标 ⚠ 的必须给出处，或改引库内既有口径、或删。（首轮是手工 grep，2026-07-23 已固化成脚本。）
首册即靠此法抓出凭空写的「30–50 个问题」（库内既有口径是 20~50 题），已改正。

## 五、验收（每批）

八道门禁全绿 + `build.py --check` 幂等 + 数字自查 + 目检；每册 MANIFEST 记一行；分批提交。

## 五·五、逐册战场预判（我先扫一遍题池给的方向，执行时以实读为准）

**批二·工程保障层**——这四册题池底子比 RAG 好，本来就偏交锋（「已经有 API 网关了」
「能省多少钱」「自建还是买托管」「已经有 Datadog 了」），所以**重点是补真空白、别硬凑**：

- **AI-Gateway**：缺**战场 7**——「网关自己挂了怎么办」。它是全流量必经，故障域最大，
  客户一定会问单点故障与降级；正文有容灾料但没立题。
- **Security**：缺**战场 1 与 6**——「你们能保证不出事吗」（安全没有绝对，怎么答不心虚）
  与「安全怎么验收」（首轮已补正文四段验收，但没立题）。
- **Evaluation**：覆盖最全。可能缺**战场 3**「我们已经有测试团队/QA 了」——传统测试与
  AI 评估的分工，这是真实异议。
- **AI-Ops**：缺**战场 1 与 6**——运维承诺什么 SLO、怎么验收「观测做到位了」。

**批三·基础层**（LLM / PE / Fine-tuning / LLM-Training）：这层离客户最远，
**最容易写成理论**——要格外守判据。真实战场多在「为什么贵/为什么慢」「要不要自己训」
「微调值不值」「模型选型」，理论本身别展开。

**批四·推理与底座**：客户是「要不要自建、买多少卡、能扛多少并发」，
战场 1（承诺并发/延迟）与战场 2（TCO）是主场。实扫题池后的缺口预判：

- **LLM-Inference**（10 题，底子最好，已有「能承诺多少并发」「别家便宜一半」）：
  缺战场 6（推理服务怎么验收）与 7（线上炸了怎么降级）。
- **AI-Infra-Compute**（8 题）：缺战场 6——**我 07-23 早些时候刚补了正文「容量与基准
  可复核：四层证据」，但没立题**，现成弹药；另可看战场 7（卡坏了谁修、返修期怎么算）。
- **AI-Infra-Platform**（7 题，全库最少）：缺战场 1（**平台的核心承诺就是利用率，
  敢承诺到多少**）与 2（平台建设的人力与周期）。
- **Data-Engineering**（7 题）：缺战场 6——**同样是我 07-23 补的正文「六条验收线 + 血缘」
  没立题**；另缺战场 1（数据质量能做到多少）。

**共性提示**：07-23 上午补的那批「生产验收」正文（AIC 四层证据、DE 六条验收线、
Security 四段闭环）都只落在正文、没立题。Security 那册已在批二补上，AIC 与 DE 照此办理。

**批五·解决方案层**：Model-Landscape 最易过期（复查日 08-31），打磨兼保鲜；
Solution-Patterns 本身就是场景册，交锋密度最高，注意别与各技术册的题重复。
