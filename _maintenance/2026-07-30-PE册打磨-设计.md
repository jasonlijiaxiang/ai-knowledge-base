## 一、体检结果

PE 册现为 **7 章 82 页**，章节结构完整，全部内容核实日停在 **2026-07-09**（21 天前）。
两类问题，性质完全不同。

### 1.1 呈现缺陷：全册 62 页页脚页码错位（本次最该先修的）

**PE 是全库唯一带页脚页码的一册**（其余 18 册页脚只有模块名与章名）。66 页带页码，
其中 **62 页与放映位不符**，最大差 6 页——放映第 46 页的页脚写着 `p.41`。

根因是历次插页（配图、增章）后页码没有按新页位重排。ppt-design-system 明确写了
「插页后页码必须重排」，但**这条没有任何机器检查**：八道门禁 + audit 17 项一道都查不出，
只有人翻到那一页才会发现。

对读者的杀伤很具体：讲义 82 页，按页码找页会找错；打印出来对不上；客户当场翻页会乱。

### 1.2 内容：一处内部打架 + 一处范式已变

**① 模型阵容与库内 Model-Landscape 册打架。**
PE 第 4 章 p46 写「GPT-5、Claude 4.7 扩展思考、Gemini 3 Pro deep think、DeepSeek R1」
（核实 2026-07-09），而库内 Model-Landscape 册写的是
「GPT-5.6 / Claude 5 / Gemini 3.1 Pro / Grok 4.3 / DeepSeek V4」（核实 07-10、07-17）。
同一个库、相隔一周的两处核实，给出两套阵容——**读者两册都翻就会看出对不上**。

**② 提示词工程本身的控制面变了，这一册还停在旧范式。**
按权威口径（Claude API 参考，2026-07-30 核实），当前主力模型上：

| 经典 PE 手段 | 现状 |
| --- | --- |
| 调 `temperature` / `top_p` / `top_k` | 在 Claude Opus 5、Fable 5、Opus 4.8/4.7 上**已移除，传了返回 400**；Sonnet 5 拒非默认值 |
| 助手预填充（prefill）强制输出格式 | 在 Opus 5 / Fable 5 / 4.6 及以后**返回 400**；改用结构化输出 `output_config.format` |
| 手写「一步步思考」 | 推理内建；对当前模型硬写长 CoT 反而多余、且烧钱 |
| 设「思考预算」`budget_tokens` | **已移除**；控制点换成 `effort`（low / medium / high / xhigh / max） |

**好消息**：本册**没有**教 temperature / top_p / prefill / budget_tokens（实测全册零命中），
所以不存在"教了已经会报错的写法"这种硬伤——它只是**没讲这件事已经变了**。
p47「通用模型 vs 推理模型」那张对照表把世界分成两类，而当前主力模型已经**都**内建思考，
这个二分正在失效。

**③ 缓存章缺一条最该讲的机制。**
p56 讲缓存省钱，Anthropic 的三个数字（读 0.1×、写 1.25× / 2×）与权威口径**完全一致**，
不用改。缺的是两条设计提示词时真正用得上的：
- **缓存是前缀匹配**——前缀里任何一个字节变了，后面全部失效。这才是「稳定部分放最前面」
  的原因，而页面上只给了结论没给机制。
- **最小可缓存前缀随模型不同，而且不是单调的**：512（Opus 5 / Fable 5）、1024（Opus 4.8 /
  Sonnet 5 / Sonnet 4.6）、2048（Opus 4.7）、4096（Opus 4.6 / Haiku 4.5）。低于门槛
  **静默不缓存**，不报错——这是最容易白花钱的一个坑。

## 二、改法

### 2.1 先修页码（呈现，与内容解耦）

写一个 `fix_footer_pagenum.py`：按放映序把每页页脚的 `p.NN` 重写成该页真实放映位，
字节级替换、只动那一个数字 run。改完 62 页。

**同批补门禁 `check_footer_pagenum.py`**（core-rules §五「错误转化为系统能力」的③）：
带页脚页码的册子，页码必须等于放映位；不带页码的册跳过。挂进 CI。
这类「机器判得出、门禁却没有」的缺口，正是这条规则要求补上的。

### 2.2 内容：三处定点，不动结构

| 落点 | 改什么 |
| --- | --- |
| p46「推理模型时代」 | 模型阵容改为与 Model-Landscape 一致的当前口径；补上「控制点是 effort 不是思考预算」 |
| p47「推理模型 vs 通用模型」 | **换承载**：从「两类模型」的二分，改成「三个旋钮的现状」——temperature 已被移除、预填充已被移除、CoT 已内建，留给你的是「把要什么说清楚」+ effort。这是用户读了会说「原来变了」的那一页 |
| p56「提示词缓存」 | 补前缀匹配机制 + 最小可缓存前缀随模型不同（含「低于门槛静默不缓存」这个坑）；Anthropic 三个数字已核对无误，不动 |

**新增 0 页，全部就地改写。** 理由：PE 册 82 页、每章深度页已接近上限，而这三处都是
「同一页说得更准」，不是「缺一整块内容」——按 ppt-rules「内容决定形式」，不该为了加内容而加页。

### 2.3 记账

- MANIFEST 时效性事实表**补「建议复查日」列**——PE 册的表只有四列（事实 / 章节 ID /
  核实日期 / 来源），没有复查日，所以 MCP 那种「到期了没人知道」的情况在这册连兜底都没有。
- 三条改动登记核实日 2026-07-30 与信源；页数不变（82），四面页数账无需回刷。
- 网页版 PE 页同批对齐（两面事实同源）。

## 三、验收

1. `check_footer_pagenum` 新门禁：PE 册 0 错位，其余 18 册跳过；故意改坏一页 → 门禁必须红；
2. audit 19/19 PASS；八道门禁 + `build.py --check` 全绿；CI 绿；
3. 渲染目检 PE 册本体改动页；
4. 抽验：PE 的模型阵容与 Model-Landscape 册逐字一致。

## 四、不做

- 不新增页、不动章节结构、不重制整册。
- 不改 p56 的三个 Anthropic 缓存数字（已核对与权威口径一致）。
- 不给其余 18 册加页脚页码（它们没有这个问题，加了反而多一份要维护的账）。
