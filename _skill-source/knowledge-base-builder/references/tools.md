# 工具目录（`scripts/` 里那 41 个东西，什么时候用哪个）

**按需读，不要通读。** SKILL.md 里只留一张「什么时候用哪个」的索引表；这份文件装的是
每个工具**为什么存在、拦的是哪次事故、有什么坑**。要用某个工具时翻它对应的那一段，
或者直接读脚本头部的 docstring——两处内容同源，脚本里那份更细。

（v9.0 从 SKILL.md 正文外置。理由与 v4.9 外置 CHANGELOG 完全一样：**工具目录是「按需读」
的东西，放正文等于每次任务都白载入一遍**。外置前它占 SKILL.md 的三成，比当年那节版本史还大。）

一条通用铁律：**除生成器与配图两件外，全部零第三方依赖**，`python3` 直接跑。
初始化或迁移一个库时，把要用的那些复制进库的 `_maintenance/`，让门禁跟着库走。

## 一、门禁（跑起来判对错的）

### `run_all_gates.sh` — 唯一的门禁清单入口

按 CI 的顺序把全部门禁跑一遍，报每道 ok/FAIL。**提交前不要挑着跑**——人靠记忆挑必然漏，
「本地绿 / CI 红」两次事故根因都是这个。末尾自检会数 `.github/workflows/gates.yml` 的
步数，与本脚本跑的道数对不上就报警（库不带 CI 时跳过自检，不报警）。

v9.0 起它是**唯一**的门禁清单：`make_share.py` 的解压自检、整库 Release 说明都改成跑它。
此前库里有四份清单，只有 gates.yml ↔ 本脚本那一对有防漂自检，另两份静默漂到
「对外说全跑了一遍、实际只覆盖 15 道里的 9 道」。

## 二、两道值得单独说的门

### `check_freshness.py` — 保鲜从看板变成门（v8.2）

每条时效性事实自报**证据等级**（A 一手 / B 二手，C 不许进成品）与**复核节奏**
（30 / 90 / 180 天）。有效复查日 = `min(复查日, 核实日期 + 节奏天)`，到期即 FAIL；
并查列契约、未来日期、章节 ID 能否解析、「不能外推」是否为空。

补的是「保鲜看板只是报表」这一格——看板可以一直红着而门禁全绿，没有任何机制强迫人去看它。
巡检第 1 级直接跑它，**不要手工比日期**。

**它同时定义了这个库的长期负荷**：30 天档每多一条，就是每月多一次联网核实。
往表里加事实前先问一句「这条真的每月都会变吗」，判据与账见 `gen_source_list.py`。

### `check_web_chapters.py` — 重组前先把安全网架好（v8.5）

网页版一旦按读者判断链重组，章节 ID 就与讲义脱钩，而既有门禁一道都发现不了。两条契约：
**默认态**（没登记「## 网页章节」的册）小节 id 必须是讲义章节 ID，结构性小节
（qa/related/sources/cloud/boundary）白名单豁免；**重组态**要求表与页面一一对应、
**每个讲义章节至少被一个网页章节承载**（重组可以打散顺序，不能丢内容）、
不再作小节 id 的旧锚点必须留隐藏别名（深链不断）。

## 三、做讲义（PPT 面）

| 脚本 | 干什么 |
| --- | --- |
| `kb_deck_build.py` | **讲义生成器**（需 `python-pptx`）：把结构化内容 JSON 渲染成合规讲义。令牌、明暗节奏、页脚、`app.xml` 全自动。页 kind：cover/toc/chapter/goals/points/steps/table/qa/handson/summary/recap/sources |
| `deck_to_json.py` | **反解器**（需 `python-pptx`，v9.0）：从生成器渲染的讲义反推整册 JSON，`--verify` 走往返自检（重渲染 → 逐页文本比对） |
| `kb_deck_text.py` | 讲义文本提取器：**按放映序**导出每页文字。放映序取自 `presentation.xml` 的 `sldIdLst`，**不是文件名数字**——插过页的册两者会错位 |
| `kb_insert.py` | zip 级插页嫁接，同步 `app.xml`。**同插入点插多页要逆序传参** |
| `kb_delete.py` / `kb_move.py` | zip 级删页 / 移动页。移动只改放映次序与标题向量，**页本身字节不动**；移完记得改眉题与页脚章名 |
| `kb_archive.py` | 安全落档：改写成品前把旧版复制进 `raw-data/history/`，自动查重名、同日顺延 `b/c` 后缀、**拒绝静默覆盖** |
| `dump_pages.py` / `scan_candidates.py` | 按放映序 dump 指定页的形状文本 / 扫配图候选页 |

### 生成器的边界与两条纪律

**它不替人做的事**：写什么、每章几页、版式选哪种、类比好不好——那些是 `ppt-rules` 与
`core-rules §六` 的活。生成器只保证「长相合规」，`audit_pptx.py` 与逐页渲染目检照跑不误
（生成器管不了「文字撑破卡片」那一格）。

1. **整册 JSON 必须入库**，存 `raw-data/讲义源.json`，由 `check_deck_source.py` 看住。
   头两册生成完 JSON 没留，结果全库唯一能兑现「改令牌就重渲染」的地方恰恰兑现不了。
2. **页脚页码默认不写**。生成器自动写页码会把库劈成两类册（v9.0 起默认关闭）——
   分叉的成本是读者侧的观感：翻到那一页像混进了另一份文件。

## 六、巡检、分发与账本

| 脚本 | 干什么 |
| --- | --- |
| `gen_source_list.py` | 从各 MANIFEST 的「来源」列派生 `_maintenance/信源清单.md`（v9.0）：把全库事实**按信源**重排、最早到期的排最前。复核按信源批处理，一个页面把挂在它上面的几条一次核完，不必为同一页翻三个模块。顺带算出并印出**每月复核负荷** |
| `make_share.py` | 整库打瘦身 zip 并**解压自检**——在解出来的那份里跑 `run_all_gates.sh`。zip 建成功只证明压缩没错，不证明拆开还是一个能用的库 |

`gen_source_list.py` 有 `--check` 但**刻意不挂门禁**：这份清单唯一的读者是巡检，
而巡检读之前先重建它，过期的中间态不会误导谁。对比 `build.py --check` 必须挂——
网页产物是读者直接看的东西。
