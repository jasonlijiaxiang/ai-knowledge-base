# 全库术语表

只收会改变判断的词：同一个词在库内指两件事、两个词常被当成一件事、客户当场会问且答偏要付代价。一看就懂的、不会误解的、模块名本身都不收。答案留在原处——这张表只给去处。

## 术语
| 词条 | 类 | 一句话 | 容易认成什么 | 去处 |
| --- | --- | --- | --- | --- |
| 代理 | 甲 | 中文一个词扛了 proxy（转发）与 agency（权限）两个意思 | AI-Gateway 与 MCP 的代理是 proxy——网关统一转发、鉴权、限流、审计，多一跳通常是毫秒级；Agent 与 Security 的「过度代理（Excessive Agency）」是 agency——给 Agent 的权限超过任务所需，出事时爆炸半径放大；Predictive-AI-MLOps 还有第三个「标签的代理量」，指混进特征的替身变量 | security#sec-agentic |
| 登记 | 甲 | 把一件 AI 的事记进一张表，对外与对内是两张不同的表 | Security 第 8 章的登记是中国监管路线的一档——调用已备案模型做的产品走应用／功能登记，周期是周级；AI-Governance 第 2 章的用途登记是组织内部的母账，一条用途一条记录，对外那几张表都从它取数，两头各记一份必然漂移 | ai-governance#gov-registry |
| 合规 | 甲 | 「合规做了吗」问的可能是两套互不相通的规则 | Security 第 8 章的合规是中国这套手续——算法与大模型备案、应用登记、内容标识、安全国标、数据出境三通道；Security 第 7 章与 AI-Governance 的合规是国际框架那套——欧盟法案的分类与时点、NIST AI RMF、ISO/IEC 42001，答的是义务落到提供者还是部署者。出海与国内是两套规则，别混谈 | security#sec-governance |
| 缓存 | 甲 | 把算过或答过的东西存下来复用，库内三种缓存省的不是同一笔钱 | LLM-Inference 与 LLM 原理的 KV／前缀缓存存的是显存里算过的 K、V，省的是重算与首字延迟、代价是吃显存；AI-Gateway 的语义缓存按向量相似度命中、直接不调模型，但「相似≠相同」，阈值太松会答错；Prompt-Engineering 的提示词缓存是计费口径 | llm-inference#llminf-kv-budget |
| 可观测 | 甲 | 把系统跑成什么样变成看得见的指标，两册盯的是不同的层 | AI-Infra-Platform 管 GPU 与集群层——卡的占用、MFU（Model FLOPs Utilization）、故障与利用率运营；AI-Ops 管应用与质量层——trace、在线评估分、漂移与 token 成本；AI-Gateway 是两者之间的数据源与统一采集层，trace id 两层贯通 | ai-infra-platform#aip-observability |
| 利用率 | 甲 | 卡到底用上了几成，库内的百分数出自不同口径 | AI-Infra-Platform 第 6 章说它有三层口径——占用率、活跃率、有效率（MFU／goodput），nvidia-smi 那个 90% 只是活跃率；LLM-Inference 与 AI-Infra-Compute 谈的「利用率 40–50%」是自建对比托管 API 的经济分水岭，是另一本账。客户报利用率时第一句要追问哪层口径 | ai-infra-platform#aip-observability |
| 路由 | 甲 | 决定这一条请求交给谁处理，库内至少四层各有一个路由 | AI-Gateway 与 Model-Landscape 的路由是模型路由——按难度与成本把请求切到不同模型，是省钱与容灾件；Agent 与 RAG 的路由是编排里的分支模式，属于写死的工作流那一档；另有 LLM-Inference 的 KV 感知路由与 LLM 原理里 MoE 的路由器，都在模型或集群内部 | ai-gateway#gw-route |
| 漂移 | 甲 | 上线后表现与当初基线偏离，库内分「有真值」与「无真值」两种 | AI-Ops 的漂移发生在没有客观真值的生成式应用上——供应商静默换权重、输出风格变了，靠嵌入距离与判官持续打分发现；Predictive-AI-MLOps 的漂移有客观真值、只是要等标签成熟，靠分布距离与成熟真值上的指标发现，且那边的铁律是「漂移不等于变差」。两边只共用采集层，判断方法不共用 | ai-ops#ops-drift |
| 评估 | 甲 | 「这东西行不行」的判定，库内几册答的不是同一个问题 | Evaluation 的评估答「答得准不准、好不好」，靠评估集与判官打分（延迟吞吐归 LLM-Inference、安全攻防归 Security）；AI-Governance 的影响评估答「会伤到谁、有多重、谁来兜、怎么申诉」，产出是几条架构约束不是分数；另有 Security 第 8 章按国标做的备案安全评估、Predictive 有真值时的离线指标，四者互不替代 | evaluation#eval-why-hard |
| 平台 | 甲 | 客户说「已经买了一套 AI 平台」时，可能指四种不同的东西 | AI-Infra-Platform 的平台是算力平台——K8s 上的 GPU 调度、切分、容错与观测；Agent 第 7 章的是低代码 Agent 平台（Coze／Dify／n8n／HiAgent），客户口中的第一个问题往往是这个；另有 Model-Landscape 第 9 章的模型平台与 AI-Ops 第 7 章的观测评估平台。先问是哪一层再报方案 | ai-infra-platform#aip-overview |
| 数据泄漏 | 甲 | 训练时用上了预测那一刻取不到的信息，离线分数虚高 | 客户数据部门说的「数据泄露」是数据外泄，属安全问题、归 Security；Predictive-AI-MLOps 说的是训练取数看见了未来、模型学会抄答案，不报错也不抛异常，交叉验证查不出。中文同一个词，先问清对方指哪个 | predictive-ai-mlops#pam-features-time |
| Task | 甲 | A2A 里一次委派的活儿：有唯一 ID、九种状态，终态不可回跳 | A2A 的 Task 是协作的基本对象（有状态工单，重试要建新 Task）；MCP 的 tasks 是长任务官方扩展（发起后拿句柄轮询查询、可取消）——两个协议里的 Task 不是一回事 | a2a#a2a-protocol |
| 推理 | 甲 | 把训练好的模型跑起来、逐 token 生成回答的过程 | LLM-Inference 全册的推理是 Inference——把模型跑起来服务请求，谈的是首字延迟、并发与账单；LLM-Training 第 6 章的「推理模型／推理时扩展」是 Reasoning——答题前先生成思维链换正确率。客户说「推理太贵」多半指前者，说「推理能力强」指后者，处方完全不同 | llm-inference#llminf-anatomy |
| 无状态（Stateless） | 甲 | MCP 现行协议核心：删握手与会话 ID，每个请求自带版本与能力 | MCP 的无状态在会话层（任意请求打任意实例，普通负载均衡就能扩容）；A2A 说 Task「有状态」在任务对象层（状态真相在服务端，客户端只是观察者）——两者不矛盾，别当成两协议方向相反 | mcp#mcp-transport |
| 性能 | 甲 | 「性能怎么样」在库内是两个互不相干的问题 | LLM-Inference 的性能是快慢与吞吐——TTFT、TPOT、并发与 goodput，靠压测拿证据；Predictive-AI-MLOps 的性能是模型预测准不准——准确率、召回这类必须等真值才算得出的指标，标签没成熟时只能估、不能当验收 | llm-inference#llminf-production |
| 选型 | 甲 | 「用什么模型」这个问题的答法，库内是两类不同的取舍 | Model-Landscape 的选型是大模型选型——榜单、价格带、许可证、多模型组合与三层路由；Predictive-AI-MLOps 的选型是表格与时序模型的算法取舍——树模型、时序、排序、异常四种数据形状各有默认解。客户问「你们用什么模型」，先分清问的是哪一类 | model-landscape#ml-selection |
| 训练 | 甲 | 用数据改动模型权重的过程，库内至少指三件不同的事 | Fine-tuning 说的训练是拿自己数据改一个已有大模型的权重、产物是 adapter；Predictive-AI-MLOps 说的是在自家历史数据上从头拟合一个预测式模型、产物是客户自己的权重资产，多数走批量打分；另有 LLM-Training 说的从零预训练，那是模型厂的事 | llm-training#llmtrain-overview |
| 注册表 | 甲 | 记「有哪些东西、哪个版本」的账，三册记的不是同一类对象 | AI-Ops 的版本注册表记 LLM 应用的六件生产工件（提示词、评估集、模型与参数、RAG 配置、工具与护栏、发布记录），回滚就是把指针指回旧 tag；MCP 的官方 Registry 是公开 server 的元数据货架，企业内网必须自建私有 registry；Predictive 的模型注册表是模型版本加批准状态 | ai-ops#ops-release |
| AI-BOM，AI Bill of Materials | 乙 | AI 系统的物料清单：用了哪些模型、数据集、依赖与版本 | 常和治理侧的「用途登记」当成同一张表：AI-BOM 记「系统里有哪些模型与组件」，用途登记记「有哪些 AI 用途、谁批的」；一条用途对应多条 AI-BOM 项，两张表由不同的人负责 | security#sec-supply-chain |
| 按 token 限流（TPM） | 乙 | 按每分钟 token 数设上限，因为成本与负载由 token 决定 | 常与按请求数限流（RPM）当成一回事：一条几万字的长请求抵得上几百条短请求，只按请求数限既管不住成本也保护不了后端——生产要 TPM 与 RPM 双维度一起限 | ai-gateway#gw-cost |
| 备案 | 乙 | 生成式 AI 服务向境内公众提供之前必须完成的监管手续 | 最常见的误区是把「登记」当「备案」：自研或微调模型对公众提供走服务备案，大模型备案 3–6 个月、双备案全流程 5–8 个月；调用已备案模型做应用走应用／功能登记，报地方网信办、周期是周级。答错直接把排期算错一个量级 | security#sec-china |
| 标签成熟期 | 乙 | 标签窗口走完、答案才揭晓的那段等待，直接决定 POC 周期 | 与数据标注常被当成一件事：标注是人打出来的，成本在人力，归 Data-Engineering；标签是等出来的，成本在时间，加人加钱都缩不短。窗口没走完就统计，正样本比例天然偏低，模型会显得很准 | predictive-ai-mlops#pam-problem-framing |
| 长期记忆 | 乙 | 跨会话保留的稳定偏好与经确认的经验，用时按需取回 | 常与 RAG 知识库当成一回事：RAG 记「组织的知识」（文档、手册、工单），记忆记「这个用户与这个 agent 的交互史」；载体技术相通（都是存储加检索），但管理与合规策略完全不同，且写回长期记忆必须过验证 | agent#agent-memory |
| DPO，Direct Preference Optimization | 乙 | 直接在「好答案 vs 差答案」对上优化，跳过奖励模型与强化学习 | 常和 RLHF 混称「对齐」：RLHF 要先训奖励模型再跑 PPO，工程重、超参敏感；DPO 一个损失函数替代整套 RL 管线，成本接近再跑一次 SFT。客户认定「对齐很贵、只有大厂做得起」，用的是旧地图 | llm-training#llmtrain-alignment |
| 多模态理解 vs 多模态生成 | 乙 | 「多模态」不是一个模型是一类能力，先分清要看懂还是要生成 | 理解侧是让模型看懂图、文档、视频与语音，选型看 MMMU／OCRBench／Video-MME 这类基准与客户的文档版式；生成侧是产出图、视频与语音，选型看流派（扩散还是自回归）、按秒或按 token 的成本账，还牵出内容标识合规。方案骨架完全不同 | multimodal#mm-what-why |
| 覆盖率 | 乙 | 高频问题里有答案的比例，量的是库里缺不缺文档 | 常与准确率混着承诺：覆盖率量「库里有没有这份文档」，是客户文档质量的镜子；答得准不准是端到端评估的事。覆盖率低该补文档，不是调模型 | data-engineering#de-quality |
| 概念漂移 | 乙 | 同样的输入，结果关系变了；模型必然失准，只有真值能证实 | 常与输入漂移（协变量漂移）混为一谈——后者只是进来的人群变了、X 与 Y 的关系没变，模型可能照样准；只有概念漂移才必然要重训。混在一起就会做出「见漂移告警就自动重训」这个本册点名最贵的动作 | predictive-ai-mlops#pam-monitoring |
| 工作流（Workflow） | 乙 | 人预先写死步骤、模型只在固定节点被调用的系统形态 | 常与 agent 混为一谈：工作流路径可控、成本可预期、每步可审计；agent 自己决定路径与步数，换来灵活也付出不确定性与 token 成本。判据是路径能不能预先写死——能用工作流解决就别上 agent，自主性是花钱买的 | agent#agent-what-why |
| goodput | 乙 | 满足 SLO 的那部分吞吐，也就是真正能对外承诺的容量 | 常被吞吐或利用率顶替：吞吐压到饱和时 SLO 早已爆表，MFU 是训练侧「标称算力吃到几成」，活跃率高也不代表净产出高。对客承诺与验收写 goodput 加分位延迟，别写饱和吞吐或 nvidia-smi 的活跃率 | llm-inference#llminf-production |
| 轨迹评估 | 乙 | 逐步检查 Agent 的中间动作：该调的工具调了吗、参数对不对 | 常和结果评估当成一回事：结果评估只看任务办成没有，管验收；轨迹评估看过程每一步，管定位。只签结果通过率，会把「中途越权却完成了」的危险成功放行 | evaluation#eval-scenarios |
| 函数调用（Function Calling） | 乙 | 模型以结构化参数决定调用哪个外部函数的机制 | 常被当成 MCP 的替代或前身：函数调用是模型「决定用哪个工具」的能力，MCP 是「工具怎么被标准接入」的协议；MCP 内部仍靠函数调用做决策，二者叠加不是二选一 | mcp#mcp-what-why |
| 坏例分流 | 乙 | 一条坏答案先判是「不知道」还是「不听话」，再定它去哪条线 | 评估集线与训练集线常被当成同一个池子：评估集管验收与回归、要留 10–20% 保留集防应试；训练集只收「不听话」的行为类坏例，知识缺的硬塞进去是白花钱——那类该补数据或更新 RAG | data-engineering#de-labeling |
| 护栏 | 乙 | 模型外的输入／输出／动作检查层，逐条拦截不安全内容 | 常被当成评估的替代品：护栏是在线的安检门、挡个案，评估是离线的体检、看整体水位；而且护栏拦得准不准，本身还要靠评估来度量。互补，不互替 | security#sec-defense |
| 间接注入 | 乙 | 恶意指令藏在模型顺带会读的外部内容里：网页、邮件、文档 | 常被当成直接注入的一个变体：直接注入来自用户本人，输入侧护栏与系统提示词加固能挡掉不少；间接注入的受害者无辜、你无法预审每段将被读到的文本，只能靠架构级防御与最小权限 | security#sec-prompt-injection |
| 结构化输出 | 乙 | 让模型只输出机器可读格式（JSON／固定字段）的输出约束 | 常把「提示词里写一句只输出 JSON」当成结构化输出：那只是请求，模型多说一句寒暄就解析失败；生产靠的是 API 的 JSON mode／function calling／强制 schema，从接口层保证格式 | pe#pe-core-techniques |
| 解决率（resolution） | 乙 | 客服 AI 真正把问题解决掉的比例，独立口径远低于厂商自报 | 与挡走率（deflection）常被混着报：挡走只是没转人工，不等于问题解决。厂商自报 51–80% 与独立口径中位 41.2% 的差距多半就出在这里；验收线要写明按哪个口径测、拿谁的工单测 | solution-patterns#sp-customer-service |
| 激活参数 | 乙 | MoE 模型每个 token 实际参与计算的参数量 | 和总参数常被混成一个「参数量」：总参数决定存储与显存（所有专家都要装进去待命），激活参数决定每 token 算力与推理成本。只看总参数会把部署卡数算错，只看激活参数会把显存门槛漏掉 | llm#llm-architecture |
| 金丝雀发布 | 乙 | 新版本先切 5–10% 流量验证「没变坏」，再决定晋升还是回滚 | 常和 A/B 实验、环境隔离混为一谈：金丝雀答「敢不敢全量」是发布安全件，A/B 答「该选哪一版」是优化工具，环境隔离是空间隔离不是流量切分；而且 LLM 金丝雀必须在金丝雀流量上跑自动评估，只看错误率与延迟等于没做 | ai-ops#ops-release |
| 记忆投毒（Memory Poisoning） | 乙 | 把恶意内容写进长期记忆，此后每次会话反复发作；OWASP 列为 ASI06 | 常与提示注入混：注入随会话重置就失效，投毒进了记忆库跨会话持续潜伏，不主动审计根本发现不了——所以防线是写入过滤、任务间清理、鉴权审计 | agent#agent-memory |
| 基准测试 | 乙 | 固定题集加统一判分的公开统考，用来横向比模型 | 常被当成选型结论：基准量通用能力、只够筛入围，还会饱和、会被应试优化；拿客户自己的题打分的自建评估集才是选型与发布的验收线，生产监控再管上线后的长期水位。三层互相不能替代 | evaluation#eval-benchmarks |
| 基座模型（Base Model） | 乙 | 只做过预训练的出厂形态：会接着往下写，不会听指令应答 | 和 instruct／reasoning 常被统称「开源模型」：base 没有指令跟随也没有安全边界，适合当二次开发底座；instruct 经过 SFT 与对齐，是面客主力；reasoning 再加 RLVR、先想后答。客户说「用 base 更便宜」，先说清直接面客的风险 | llm-training#llmtrain-overview |
| 开放权重（open weight） | 乙 | 只给训练好的权重文件，不给训练数据与训练代码 | 与「开源」常被混着说：按 OSI 的 OSAID（Open Source AI Definition）口径，开源还要开放训练数据信息、架构与训练代码，市面上主流「开源模型」几乎都只到开放权重这一档。能不能商用要看许可证三级分类，不看这两个词 | model-landscape#ml-license |
| LoRA，Low-Rank Adaptation | 乙 | 冻结底座只训低秩旁路，产物是几十 MB 的 adapter | 和全参微调常被一并说成「微调」，但报价差一个数量级：全参解冻全部权重、显存约参数量×16 字节、要集群；LoRA 可训参数不到 1%，单卡起步、adapter 可热插拔可秒级回滚，学得少也忘得少。要深度灌注新知识才轮到全参 | fine-tuning#ft-methods |

| RLVR，Reinforcement Learning with Verifiable Rewards | 乙 | 奖励来自机器可判的对错、而非人类打分的后训练 | 容易和 RLHF 当成一回事：RLHF 靠奖励模型「品」，会被答长、堆免责这类讨好钻空子；RLVR 只在数学、代码这类答案可验证的任务上成立，写作与共情仍要回到偏好对齐。客户要「行业推理模型」，先问任务能不能机器判分 | llm-training#llmtrain-reasoning |

| 上下文工程（Context Engineering） | 乙 | 在有限窗口里决定给模型看什么，让每个 token 都是高信号 | 常与提示词工程混：提示词工程管一次调用「怎么说」（角色、四要素、分隔符、少样本），上下文工程管「给模型看什么」（压缩、筛选、外置记忆）；窗口变大不等于注意力变多，塞得越满单位信息越被稀释 | agent#agent-context |
